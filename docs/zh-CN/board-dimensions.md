# 十个产品维度

[English](../en/board-dimensions.md) · 简体中文

## 职责划分

| 维度            | 负责什么             | 验收重点                     |
| --------------- | -------------------- | ---------------------------- |
| 工作区与频道    | 组织目标及可见范围   | 归档阻止新执行，历史可读     |
| Thread 与上下文 | 讨论、决策、交接素材 | 有来源、可分页、有限注入     |
| 任务协调        | 认领、派发和责任     | 单一有效持有者、幂等         |
| 身份与权限      | 谁能做什么           | 默认拒绝；共享密钥非独立身份 |
| 执行与路由      | 节点、适配器和原执行 | 跨服务保持身份、交互和终态   |
| 事件与激活      | 哪个事实唤醒后续动作 | 不因重复事件重复执行         |
| 外部连接器      | 消息渠道与外部输入   | 授权、重放与来源边界         |
| 流程与验收      | 阶段、证据和审查     | 版本固定，验收针对确切成果   |
| CLI 与工作台    | 人和脚本的统一入口   | 同一协议，明确错误与待处理   |
| 持久化与运维    | 事务、恢复、备份     | 重启不丢记录、不重发未知执行 |

## 状态分层

认领状态、Runtime 结果、业务阶段分别表达。模型通过有权限的业务命令请求动作，服务端确认事件并推进流程。任务卡和 Thread 是产品入口，不应让用户必须理解事件引擎。

## 推进次序

先完成显式执行与人工验收，再补独立凭证、自动激活、外部输入、依赖图和受限自动验收。此文为规划；已实现能力以 P1 和部署文档为准。
