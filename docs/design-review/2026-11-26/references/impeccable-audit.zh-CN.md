# 表单与手机审计

[English](impeccable-audit.md) · 简体中文

本轮聚焦项目、例行任务、Agent、任务及引用表单和手机导航。它是工程与设计审计，
不代表 WCAG 认证或真机可用性研究。Impeccable4.11.1 已安装；engine0.1.31
从官方 npm 平台包获取，SHA-256 与 skill 的校验清单一致。首次 context 启动器
缺少执行位，因此直接读取了现有产品/品牌文档，没有编造 PRODUCT.md 或 DESIGN.md。
Modern Web Guidance1.0.2 已按指定命令安装，并读取 forms、dialog、
form-factor-adaptation、browser-ui-theming 规范。

已修复：P1 手机旧规则覆盖字号，实际仍为14px；P2 密钥输入框出现8px内间距与
第二层边框；P2 表单32/36px高度、4–6px圆角和重复分隔框混用；P3 权限卡片单侧
强调边框。现在桌面表单44px、手机48px，手机文字16px，字段圆角12px，弹窗和
对话输入区圆角20px。焦点清晰可见，错误样式只在用户交互后出现。

Impeccable 最终源代码检测返回 `[]`。它没有扫描认证后的渲染页面，不能代替
逐像素对比度或屏幕阅读器检查。本轮没有发现尚未修复的 P0/P1；原有 Base UI/coss
结构与行为保留，没有叠加另一套原生弹窗或额外 polyfill。

手机验收使用 Chromium CDP 模拟触摸，完成草稿输入、打开下拉框、切换到另一个真实
fixture Agent 并取消，断言名称/目录变化且项目没有保存。320×600和320×360布局
视口用于验证滚动与按钮可达性，不能等同于真机键盘。原测试继续覆盖嵌套 Escape、
焦点恢复、原始身份、隐藏字段校验、密钥、中英文和主题的 session 记忆。

原生输入保留 IME、复制粘贴和校验；使用 `:user-invalid` 避免空白必填项一打开就报错。
支持的浏览器通过 `interactive-widget=resizes-content` 调整布局视口，其他浏览器
忽略该选项并保留可滚动弹窗。滚动条使用正常尺寸，选区与光标随主题变化。
此前 Taste 的营销页检测问题仍单独记录，没有改写为通过。

最终本地检查176项测试，154通过、22平台跳过；32组浏览器检查通过，fixture模型调用为0。浅/深色字段边界对比度3.08/3.94，placeholder4.67/5.46，焦点6.39/7.01。两位独立代码审阅者已批准本轮UI修复。
