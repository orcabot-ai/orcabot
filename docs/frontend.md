# Frontend architecture

The owner selected the TanStack stack and both light and dark appearance on
2026-11-24. The browser application uses React and Tailwind CSS in a pnpm workspace.

| Package          | Responsibility in Orcabot                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| TanStack Start   | Vite application framework and prerendered SPA shell                                                          |
| TanStack Router  | Typed file routes, conversation deep links, back/forward navigation                                           |
| TanStack Query   | Workspace, conversation, run detail, attention and artifact server state; cursor pages; mutation invalidation |
| TanStack Form    | Unlock, Agent/target configuration, composer, interaction response, investigation note and artifact forms     |
| TanStack Table   | Attention records with conversation, outcome and update time, plus selected-record controls                   |
| TanStack Virtual | Measured, variable-height run rows in conversations containing more than eight loaded runs                    |

## One service and one authority

Start runs in SPA mode. Production builds produce `apps/web/dist/client/_shell.html`
and assets. Fastify serves these together with the existing authenticated API and
SSE endpoints. Conversation URLs also return the static shell, so bookmarks and
reloads work without a second application server. The generated Start server build
is used during prerendering; it is not a second production service.

The root route contains document metadata, presentation bootstrap and providers.
It does not load workspace data during prerendering. Application routes disable
SSR, and authenticated data is fetched in the browser after fragment-key exchange.
The shell contains no service key, remote credentials or operator conversation.

Each router owns one QueryClient. Query is a read cache, not a replicated SQLite
store. The API remains authoritative. Mutations do not automatically retry task
admissions or interactions. Focus refetch and active-run polling refresh run
summaries; SSE tails durable output for mounted run cards. Stream cleanup stops
browser observation without cancelling Runtime execution. Event display windows
remain bounded, and earlier runs/events are explicitly requested.

Large conversations use measured virtual rows and stable run IDs. Unmounted rows
release SSE subscriptions. Existing execution continues on the server. Loading an
earlier page retains the newer run metadata so unresolved work still blocks another
turn. This is not a production load-test result.

## Appearance

The top-bar **Color theme** selector offers **System**, **Light** and **Dark**. The
unlock page also exposes it. Semantic CSS variables cover surfaces, inputs, text,
borders, code, focus indicators, approval/warning/error states and all dialogs.

Appearance is stored in localStorage under `orcabot.theme`. Language is stored
separately in sessionStorage under `orcabot.locale`. Service keys are never
stored in either location. System mode tracks OS appearance changes; storage
events keep open tabs aligned. If browser storage is unavailable, the current
page still supports theme changes. A small static head script applies the saved
choice before styles paint. The server calculates exact SHA-256 CSP hashes for
shell inline scripts, including Start hydration, instead of allowing arbitrary
inline JavaScript. Restart the service after replacing a production build so its
CSP matches the deployed shell and assets.

## Development

`pnpm dev` runs the Fastify API on port 4310 and the Start Vite development server
on port 5173. Export `ORCABOT_PUBLIC_URL=http://127.0.0.1:5173` before starting it;
the printed login URL and same-origin checks then use the development UI origin.
Vite proxies `/api` to Fastify. Production uses `pnpm build` followed by `pnpm start`.

`src/routeTree.gen.ts` is generated by Start and retained for immediate TypeScript
checks in a fresh checkout. Do not edit or format it manually. New route files
regenerate it during development/build.

## Language and visual direction

The interface supports English (`en`, default) and Simplified Chinese (`zh`).
The **Language** selector is available on the unlock page and in the workspace
header. `I18nProvider` owns the current locale; labels, accessible names, errors,
execution statuses, and dates react to changes without clearing form inputs or
restarting work. Document language and title also follow the selection. Agent
output, conversation titles, artifact content, model IDs, adapter names, and
transport values remain unchanged.

Language is a **browser tab session preference**, independent of authentication.
Refreshing or navigating within the tab retains it. Separately opened tabs have
independent storage; browsers can initially copy sessionStorage into a duplicated
tab, after which the two preferences are independent. A new tab session defaults
to English. Blocking storage keeps language switching usable in memory. The
service uses a shared key and has no per-user profile or server-wide language
setting. This behavior intentionally does not change the signed session cookie.

English message text forms the lookup keys in `messages.ts`; `locale.ts` contains
storage and interpolation helpers. Unknown runtime diagnostics retain their
readable technical text. New locales should extend the catalog and locale union.

The owner's visual reference sets the direction across the gate, workspace,
configuration, attention, artifacts, and execution views: a muted gray/lavender
background, white surfaces in light mode, restrained lavender selection, dark
primary buttons, generous spacing, thin borders, rounded corners, and subtle
shadows. Dark mode uses the same semantic tokens and hierarchy. Compact-height
and mobile layouts keep essential controls reachable; reduced-motion preferences
suppress decorative animation.
